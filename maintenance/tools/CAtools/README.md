Suite of tools to manage CA and certificates

The CA is not shared with this bundle for obvious security reasons.

# 1. Generation of CA

Simply execute `./generateCA.sh`. It will create a 
directory `CA` with all the necessary files.

The CA key is central to the security of the infrastructure. It should never ever
leave the computer where it was generated, and the permissions must be such
that only the LDCS security administrators can access it.

# 2. Generation of single host certificate

A CA must be present for the relevant script to work, see §1

run

```
./generatehostcert.sh servername
```

The generated files will be located in a subfolder inside hostcerts/

# 3. Generation of single user certificate

A CA must be present for the relevant script to work, see §1

run

```
./generateusercert.sh 'User Name'
```

The generated files will be located in a subfolder inside hostcerts/

# 4. Generation of all relevant certificates

This script uses the other script to generated all needed certificates.

A file hostnames.txt should contain all the names of the LDCS servers,
one per line, prior to execution.

A CA must be present for the relevant scripts to work, see §1

run

```
createALLLDCScerts.sh
```

All the files will be generated in the respective folders.

# 5. Generation of tarballs to send to the centers

The script `createTarballs.sh` simply collects the data generated by `createALLLDCScerts.sh` and prepares it
to be shipped to the computing centers -  `createALLLDCScerts.sh` must be run prior to this script.
